# FEL DRONE — I18N — Bilingual Foundation FR/AR — V10

> V10 prepares architecture/documentation for FR/AR without half-translated UI.
> No framework migration just for i18n.

## Current State — V10
- **Language:** French only (`lang="fr"` in template.html, `fr_DZ` locale)
- **Content source:** Single source `src/data/content.ts` — all copy centralized, not hard-coded in JSX
- **No half-translation:** UI is 100% French, no mixed FR/AR strings
- **No framework migration:** No Next.js, no i18n library added — keeps Vite + React 19 + TypeScript strict, no extra dependency

## Why FR first
- Company implantation: El Tarf, Algérie — French is primary business language for corporate site
- All existing content, SEO, legal, contact validated in French
- Arabic support is prepared at architecture level, not shipped as broken half-translation

## Architecture Prepared for FR/AR

### 1. Content centralization (done)
- `src/data/content.ts` exports `company`, `team`, `services`, `faq`, `navLinks`, `sectors`, `methodSteps`, `demonstrationItems`, `equipmentCapabilities`
- Every factual value from company dossier, not hard-coded in components
- Future: extend to `content.fr.ts` / `content.ar.ts` or `content/{fr,ar}.ts` without touching layout logic

### 2. Typography (V10)
- **V10 direction:** IBM Plex Sans single superfamily — supports Latin and Arabic glyphs (Plex Sans Arabic exists)
- Current: `IBM Plex Sans` loaded via Google Fonts (400,500,600,700) — covers FR, can be extended to Arabic with `IBM Plex Sans Arabic`
- No second family — keeps bundle small, avoids AI-generated look
- `src/index.css` defines `--font-sans` and `--font-display` both as IBM Plex Sans — one family

### 3. Layout & RTL foundation (prepared, not active)
- No RTL CSS active yet — site is LTR French
- Foundation for RTL:
  - Use logical properties where possible (`margin-inline`, `padding-inline`) — already used for safe-area guard in `index.css`
  - Avoid hard-coded `left/right` in new components — prefer `inline-start/end` for future
  - Current components use `left-4`, `right-4` for badges — acceptable for FR, will need logical refactor for AR
  - Documented here, not yet migrated — to avoid half-translated UI
- When AR is activated:
  - Add `dir="rtl"` on `<html>` based on locale
  - Swap `IBM Plex Sans` → `IBM Plex Sans Arabic` for Arabic
  - Audit all `left/right`, `ml/mr`, `pl/pr`, `text-left/right` → logical equivalents
  - Test navigation, form, header, footer in RTL

### 4. SEO & meta (FR truthful, AR prepared)
- `template.html` has `lang="fr"`, `og:locale=fr_DZ`, canonical `https://www.feldrone.dz/`
- For AR: will need `hreflang` alternates, `og:locale:alternate=ar_DZ`, separate sitemap entries
- Currently: single locale, no invented alternates

### 5. Contact form — Wilaya du besoin (V10)
- Field "Wilaya du besoin" added — aligns with Algerian context, useful for FR and future AR
- Label will be translated when AR ships, but field key `wilaya` stays stable for API
- API contract preserved: `POST /api/quote` accepts `wilaya` optional for backward compat, required for new V10 forms

### 6. What NOT to do (per spec)
- Do NOT create half-translated interface — no mixed FR/AR strings
- Do NOT migrate to Next.js, i18next, or any framework just for i18n — keep Vite
- Do NOT invent Arabic copy — wait for company-validated translation
- Do NOT add language switcher until AR content is fully validated
- Do NOT change Vercel settings/infrastructure for i18n

### 7. Future Implementation Steps (when AR is authorized)
1. Company provides validated Arabic translations for all fields in `content.ts`
2. Create `src/data/content.ar.ts` with same shape, Arabic strings
3. Create `src/lib/i18n.ts` — tiny locale switcher (no library), `localStorage` for preference, `navigator.language` fallback
4. Update `template.html` to support dynamic `lang` and `dir`
5. Load `IBM Plex Sans Arabic` when locale=ar
6. Add `docs/I18N.md` validation checklist: no hard-coded FR strings in components, all copy from content
7. Test: desktop, mobile, navigation, contact form (Nom→الاسم, Téléphone→الهاتف, etc.), logo/header/footer, service sections, RTL
8. SEO: add `hreflang`, sitemap with `/ar/` alternate, OG locale alternate

### 8. Current Validation
- `npm run typecheck` — ensures no hard-coded i18n break
- `npm run build` — single superfamily, no extra dependency
- No secrets, no fake translations
